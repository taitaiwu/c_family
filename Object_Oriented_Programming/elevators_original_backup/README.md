# 物件導向程式設計專題：多部電梯系統模擬程式

## 作業背景與目的
在物件導向系統分析中，我們會請需求使用者用自然語言描述系統功能。程式設計師會從這段描述中圈選出名詞、代名詞、名詞片語，作為物件導向中「類別（Class）」的候選者。接著透過篩選、精煉，決定最終的系統架構。本作業請仔細閱讀下方的「系統需求敘述」，利用上述方法找出所有必要的類別，並使用 C++ 語言實作出一套功能完整的電梯模擬程式。

## 系統需求與敘述
這是一個用來評估辦公大樓運輸效率的電梯模擬系統。整棟大樓具有特定高度的樓層總數，並由多部電梯共同組成的電梯系統負責運作。每部電梯內部都裝有控制面板，面板上有許多樓層按鈕供人按下。每部電梯都有其獨立的移動狀態（如：上升中、下降中、靜止中），且每一部電梯都有其載重量限制。電梯的車廂門具有安全機制，在開門與關門之間會停留固定的開啟時間。

在每層樓的電梯等候區，都設有樓層電梯大廳。大廳牆上裝有上行按鈕與下行按鈕。當大廳按鈕或電梯內部的樓層按鈕被按下時，這些請求會統一傳送給系統的中央調度器。中央調度器會根據特定的調度演算法，指派最合適的電梯前往該樓層服務。

系統在運作時，需要依賴一個模擬計時器來推進時間。每推進一個時間單位（例如一秒），系統就會透過隨機變數產生器，根據設定的到達機率在特定樓層隨機生成數名乘客。每一位乘客都有其自身重量。當乘客在某個樓層的大廳誕生時，他會根據亂數決定自己想去的目的樓層。乘客會走向大廳，按下對應的方向按鈕，並進入等候隊列中。當電梯到達並開門時，等候隊列中的乘客會依序進入電梯車廂，直到電梯滿載（超過載重量限制）為止。進入車廂後，乘客會按下電梯內的目標樓層按鈕。當電梯到達目的樓層後，乘客便會離開電梯。

最後，系統必須包含一個數據統計器。在模擬結束後，它需要讀取並計算所有乘客的平均等候時間（從誕生到進入電梯）與平均搭乘時間（從進入電梯到離開），並將這些統計結果輸出成一份模擬報告。

## 實作建議與步驟

### 第一階段：名詞萃取與類別設計（物件導向分析）
1. 圈選名詞：請列出文本中出現的所有名詞（例如：大樓、樓層、電梯、乘客、中央調度器、計時器...）。
2. 篩選候選者：
    * 剔除重複、屬於同義詞或過於抽象的名詞。
    * 釐清哪些名詞適合當作「類別（Class）」，哪些名詞其實只是類別裡的「屬性（Attribute）」（例如：乘客重量、移動狀態）。
3. 繪製關係：決定類別之間的關係（Has-a 組合關係，或是 Is-a 繼承關係）。

### 第二階段：程式實作要求（C++）
* 多檔案編譯：每個類別必須宣告於 `.h` 標頭檔，並於 `.cpp` 檔實作。
* 隨機性：必須使用 C++ `<random>` 函式庫來實作乘客生成率與目的樓層的亂數。
* 設定彈性：樓層數、電梯數量、電梯載重上限、乘客產生機率、模擬時間…，**必須能透過外部設定檔或在程式啟動時由使用者輸入**

## 評分標準
1. **物件導向設計架構及文件** (60%)：是否完整設計所有類別，每個類別的成員變數、成員函式是否完整，是否清楚定義類別間的關係？這部分的設計請以各類別的定義檔(.h)呈現，程式註解必須充分表達設計概念。
2. **模擬邏輯正確性** (20%)：多部電梯是否能正常移動、接送乘客？時間推进與亂數生成是否正確？
3. **結果與數據輸出** (20%)：是否能正確產出模擬報告，且數據符合邏輯？
